# 案件01: 新入社員PCキッティング対応(Windows初期セットアップ)

## 案件カテゴリ

クライアントPCキッティング(初期セットアップ) / IT運用サポート業務

サーバー構築エンジニアを目指す方にとって、PCキッティングは「地味だけれど全ての基本」となる作業です。OSの初期設定、ユーザー管理、ネットワーク確認、Windows Updateといった要素は、そのままサーバーの初期構築作業にも通じる考え方です。まずはクライアントPCで手順の「型」を身につけましょう。

## この案件で身につくスキル

- [ ] Windowsの初期セットアップウィザード(OOBE)の流れを理解する
- [ ] コンピューター名(PC名)を社内の命名規則に沿って設定する力
- [ ] ローカルユーザーアカウントの作成、管理者権限と標準ユーザーの違いの理解
- [ ] PowerShell(コマンドプロンプトでも可)での基本操作(`net user`など)
- [ ] Windows Updateの適用と再起動対応の実務フロー
- [ ] `ipconfig`や`systeminfo`を使ったネットワーク・PC情報の確認方法
- [ ] 資産管理台帳への記録という、情シス・運用現場ならではの「型」

## 想定シナリオ(依頼内容)

あなたは社内SE(社内のIT担当者)として働いています。ある日、総務部から次のような依頼が届きました。

> 「来月1日付で新入社員が1名入社します。営業部への配属予定です。貸与するノートPCを1台、事前にセットアップしておいてもらえますか? PC名は社内ルールに従って、ユーザーアカウントも作成しておいてください。あと、資産管理台帳への記録もお願いします。」

このように、実際の現場では「Windowsをただインストールする」だけでなく、**社内ルールに沿った名前付け・アカウント発行・資産管理**までを一連の流れとして求められることがほとんどです。今回はこの一連の流れを、初心者にもわかりやすい手順で体験していきます。

## 事前準備・必要な環境

- [ ] セットアップ対象のWindows PC(実機、または検証用の仮想マシン(VM: Virtual Machine、PCの中に作る仮想的なコンピューター)でも可)
- [ ] Windows 10またはWindows 11のインストールメディア、もしくはOSがプリインストールされたPC
- [ ] 有線LANケーブル、またはWi-Fi接続情報(SSID・パスワード)
- [ ] ローカル管理者権限で操作できるアカウント
- [ ] 依頼内容の詳細(利用者の氏名、配属部署、貸与PCの種類など。本記事では「佐藤太郎さん・営業部」を例にします)
- [ ] 資産管理台帳のフォーマット(Excelなどの表計算ソフトで可)
- [ ] 社内資産命名規則のドキュメント(なければ本記事の例を参考に自分で作成してもOK)

VM環境で練習する場合は、Hyper-VやVirtualBoxなどの仮想化ソフトを使い、Windowsの評価版イメージなどで実習環境を用意すると安全に繰り返し練習できます。

## 作業目的(ゴール)

- 新入社員が入社初日から迷わず業務を始められる状態のPCを用意すること
- 社内ルール(命名規則・アカウントポリシー)に沿った設定を行うこと
- ネットワークに正常接続でき、最新のWindows Updateが適用された状態にすること
- 誰が見ても管理状況がわかるよう、資産管理台帳に正しく記録すること

## 作業手順(詳細)

### 手順1: Windows初期セットアップウィザードを進める

PCの電源を入れると、Windowsの初期セットアップウィザード(OOBE: Out-Of-Box Experience、箱から出した状態から使えるようにする初期設定画面)が起動します。以下の流れで進めます。

1. 地域(日本)を選択し、キーボードレイアウト(日本語入力の場合は「Microsoft IME」)を設定する
2. ネットワークへの接続(Wi-Fiがあれば接続、有線なら自動認識されることが多い)
3. ライセンス条項への同意
4. アカウント作成画面が表示されたら、ローカルアカウント(Microsoftアカウントに紐付かない、そのPC単体だけで使えるアカウント)で進める
   - Windows 10の場合: サインイン画面で「Microsoftアカウントを持たないユーザーを追加する」を選択します
   - Windows 11の場合: ネットワークに接続しないまま進めると表示される「制限されたセットアップで続行」(オフラインアカウント)を選択します
5. プライバシー設定(位置情報、診断データ送信など)は社内ポリシーに従って選択する

> ポイント: 企業PCでは、個人のMicrosoftアカウントでのセットアップを避け、ローカルアカウントで初期セットアップを完了させるのが一般的です。ここで作るアカウントはあくまで作業用の仮アカウントで、業務で実際に使うアカウントは手順3で改めて作成します。

### 手順2: コンピューター名(PC名)を社内命名規則に沿って変更する

社内では機器を一意に識別するため、PC名にも命名規則を設けるのが一般的です。例えば以下のようなルールです。

```text
[拠点コード]-[部署コード]-[管理番号4桁]
例: TYO-EIG-0125 (東京拠点・営業部・管理番号125)
```

| 部分 | 意味 | 例 |
|---|---|---|
| 拠点コード | 東京(TYO)、大阪(OSA)など事業所を表す3文字 | TYO |
| 部署コード | 営業部(EIG)、総務部(SOM)など部署を表す3文字 | EIG |
| 管理番号4桁 | 資産管理台帳で採番する連番 | 0125 |

設定手順は次のとおりです。

1. 「設定」→「システム」→「バージョン情報」(「詳細情報」と表記される場合もあります)を開く
2. 「デバイスの仕様」欄にある「名前の変更」ボタンを選択する(見当たらない場合は、`Win+R`キーで「ファイル名を指定して実行」を開き、`sysdm.cpl`と入力してEnterを押すと表示される「システムのプロパティ」画面の「コンピューター名」タブから「変更」ボタンを押しても設定できます)
3. 命名規則に沿った名前を入力する
4. 再起動を求められるので、指示に従って再起動する

現在のPC名を確認するだけであれば、PowerShell(またはコマンドプロンプト。以降どちらでも同じ結果になる操作はPowerShellの実行例で統一します)で以下のコマンドを実行します。管理者権限は不要です。

```powershell
hostname
```

### 手順3: ローカルユーザーアカウントを作成する

新入社員が普段使うアカウントは、原則として**標準ユーザー**で作成します。管理者権限を渡してしまうと、誤操作で設定を壊したりマルウェアの被害が広がったりするリスクが高まるためです。

**GUIでの作成手順**

1. 「設定」→「アカウント」→「家族とその他のユーザー」(Windows 11では「その他のユーザー」)を開く
2. 「アカウントの追加」→「このユーザーのサインイン情報がありません」→「Microsoftアカウントを持たないユーザーを追加する」を選択
3. ユーザー名(例: `sato_taro`)とパスワードを設定
4. 作成後、そのアカウントを選択して「アカウントの種類の変更」を確認し、既定では「標準ユーザー」になっていることを確認する

**PowerShellでの参考手順(`net user`コマンド)**

`net user`はコマンドプロンプトの代表的なコマンドの一つですが、PowerShellからも同じように実行できます。ユーザー作成にはローカル管理者権限が必要なため、PowerShellを「管理者として実行」した上で操作しましょう。

```powershell
net user sato_taro Passw0rd! /add
```

作成したアカウントの一覧を確認するには次のコマンドを使います。

```powershell
net user
```

管理者グループに所属しているか(=管理者権限を持つか)を確認したい場合は、以下のコマンドで確認できます。こちらは標準ユーザー権限でも実行できます。

```powershell
net localgroup Administrators
```

入社初日に本人がパスワードを設定し直せるよう、「次回ログオン時にパスワードの変更を必須にする」設定もあわせて行っておくと安心です。`net user`では以下のように`/logonpasswordchg:yes`オプションを指定します。

```powershell
net user sato_taro /logonpasswordchg:yes
```

GUIから同じ設定をしたい場合は、「コンピューターの管理」(スタートボタンを右クリック→「コンピューターの管理」、または`Win+R`→`compmgmt.msc`でも起動できます)→「ローカルユーザーとグループ」→対象ユーザーのプロパティを開き、「次回ログオン時にパスワードの変更が必要」にチェックを入れます。

> 補足: 管理者アカウントと標準ユーザーの違いは、「ソフトウェアのインストールやシステム設定の変更ができるかどうか」です。日常業務は標準ユーザーで行い、必要なときだけ管理者アカウントでログインして作業する、というのが情報セキュリティ上の基本の考え方です。

### 手順4: Windows Updateを適用し、再起動に対応する

1. 「設定」→「Windows Update」を開く
2. 「更新プログラムのチェック」をクリックする
3. 更新プログラムが見つかったらダウンロード・インストールが始まるので待つ
4. 再起動が必要な場合は、作業に影響がないタイミングで再起動を実施する
5. 再起動後、再度「更新プログラムのチェック」を行い、「最新の状態です」と表示されるまで繰り返す

大型の機能更新プログラムが含まれる場合、1回の再起動では終わらないこともあります。「最新の状態です」と表示されるまで、焦らず何度か確認するのがコツです。

### 手順5: ネットワーク設定とPC情報を確認する

PowerShellを開き、以下のコマンドでネットワーク接続状況を確認します。管理者権限は不要です。

```powershell
ipconfig /all
```

このコマンドで、IPアドレス・サブネットマスク・デフォルトゲートウェイ・MACアドレス(ネットワーク機器ごとに割り当てられた固有の物理アドレス)・DNSサーバーの情報などが確認できます。IPアドレスが正しく割り当てられているかを確認しましょう。`0.0.0.0`や`169.254.x.x`のようなアドレスが表示されている場合は要注意です。`169.254.x.x`は、DHCP(Dynamic Host Configuration Protocol、IPアドレスを自動的に割り当てる仕組み)のサーバーからアドレスを取得できなかったときにWindowsが自動的に割り振る仮のアドレス(APIPA)で、ネットワーク未接続や設定不備のサインです。

PC全体の情報(OSバージョン、ビルド番号、メモリ容量など)をまとめて確認したい場合は、以下のコマンドを使います。

```powershell
systeminfo
```

### 手順6: 資産管理台帳に記録する

最後に、セットアップした内容を資産管理台帳に記録します。台帳には最低限、以下の項目を記載しましょう。

| PC名 | IPアドレス | 利用者名 | 部署 | セットアップ日 | 備考 |
|---|---|---|---|---|---|
| TYO-EIG-0125 | 192.168.10.101 | 佐藤太郎 | 営業部 | 2026-08-30 | 標準ユーザーで作成済み |

この記録があることで、後から「このPCは誰が使っているか」「IPアドレスが重複していないか」などをすぐに追跡できるようになります。地味に見えますが、運用現場では非常に重要な作業です。

## 完了確認チェックリスト

- [ ] PC名が社内命名規則(拠点コード-部署コード-管理番号)通りに設定されているか
- [ ] 作成した標準ユーザーでログインできるか(パスワード含む)
- [ ] 管理者アカウントと標準ユーザーの権限が意図通りに分かれているか(`net localgroup Administrators`で確認)
- [ ] 有線LANまたはWi-Fiでネットワークに接続できているか(`ipconfig /all`でIPアドレス取得を確認)
- [ ] Windows Updateが最新の状態になっているか(再起動を含めて確認済みか)
- [ ] `systeminfo`でOSバージョンやビルド番号を確認し、記録したか
- [ ] 資産管理台帳にPC名・IPアドレス・利用者・セットアップ日が記録されているか

## よくあるエラーと対処法

| 症状 | 想定原因 | 対処法 |
|---|---|---|
| Windows Updateでエラーコード`0x80070643`が出る | 更新プログラムのインストール中に何らかの障害が発生 | PCを再起動してから再度更新を試す。改善しない場合はWindows標準の「Windows Updateトラブルシューティングツール」を実行する。それでも直らない場合は、管理者として開いたPowerShellで`sfc /scannow`(システムファイルの破損チェック・修復)や`DISM /Online /Cleanup-Image /RestoreHealth`(Windowsイメージの修復)を試す。ディスクの空き容量不足が原因のこともあるため、あわせて容量も確認する |
| ユーザーアカウントがロックアウトされる | パスワードを規定回数以上間違えて入力した(社内のセキュリティポリシーでロックアウトのしきい値が設定されている場合に発生します。既定のローカル設定では無効になっていることが多いですが、企業では有効化されているケースがよくあります) | 管理者アカウントでサインインし、「コンピューターの管理」→「ローカルユーザーとグループ」からロックを解除する、または`net user`コマンドでパスワードを再設定する。以後は入力ミスに注意し、パスワードは社内ルールに従った安全な方法で新入社員に共有する |
| ネットワークに繋がらない(「インターネットなし」と表示される) | LANケーブルの挿し忘れ・断線、またはWi-Fi未設定 | ケーブルの両端がしっかり挿さっているか目視確認し、別のポートに挿し直してみる。Wi-Fiの場合は「設定」→「ネットワークとインターネット」からSSIDを選び、パスワードを入力して接続し直す。それでも直らない場合は、PowerShellで`ipconfig /release`→`ipconfig /renew`を実行し、IPアドレスの再取得を試す |

## 覚えておきたいポイント(暗記のコツ)

Windowsキッティングの基本の流れは、次の語呂合わせで覚えるのがおすすめです。

**「名前(PC名)→ 人(ユーザー)→ 更新(Update)→ 確認(ipconfig)」**

| 順番 | やること | 主なコマンド・操作 |
|---|---|---|
| ① 名前 | コンピューター名の設定 | 設定→システム→バージョン情報、`sysdm.cpl` |
| ② 人 | ローカルユーザーアカウントの作成 | `net user`、設定→アカウント |
| ③ 更新 | Windows Updateの適用 | 設定→Windows Update |
| ④ 確認 | ネットワーク・PC情報の確認と台帳記録 | `ipconfig /all`、`systeminfo` |

イメージしにくいときは、「新しい家に引っ越したとき」に例えると覚えやすくなります。表札を出し(①名前)、住む人を登録し(②人)、電気・ガス・水道といったライフラインを最新の状態に整え(③更新)、最後にちゃんと使えるか確認する(④確認)、という流れと同じです。

この順番で覚えておくと、現場で「次に何をすればいいんだっけ?」と迷ったときに、指差し確認の感覚ですぐ手順を思い出せるようになります。

## 振り返り・発展課題

今回の作業を振り返り、次のステップにも挑戦してみましょう。

- [ ] 複数台のPCをセットアップする場合、1台ずつ手作業で行うのは大変です。Windowsの「回答ファイル(unattend.xml)」や、社内で使われることの多いMDM(Mobile Device Management、複数端末を一元管理する仕組み)ツールについて調べてみましょう
- [ ] グループポリシー(GPO: Group Policy Object、Windowsドメイン環境で複数PCの設定を一括管理する仕組み)を使うと、パスワードポリシーやアカウント権限をまとめて管理できます。Active Directory(AD、社内のユーザーやPCを一元管理するWindowsサーバーの仕組み)の学習に進む足がかりにしてみましょう
- [ ] 資産管理台帳をExcelの手作業ではなく、資産管理ツールやスプレッドシートの自動連携で運用する方法も調べてみると、より実務に近い視点が身につきます
