# 案件08: クラウド基礎構築案件(AWS無料枠)

## 案件カテゴリ

クラウドインフラ構築(AWS/パブリッククラウド)

## この案件で身につくスキル

- AWS(Amazon Web Services、世界的に利用されている代表的なクラウドサービス)アカウントの作成と初期設定の知識
- EC2(Elastic Compute Cloud、AWS上で仮想サーバーを借りられるサービス)インスタンスの起動・操作
- セキュリティグループ(AWSにおける仮想的なファイアウォール機能)によるアクセス制御の考え方
- SSH鍵(公開鍵・秘密鍵のペアを使ったログイン認証方式)の管理とパーミッション(ファイルへのアクセス権限)設定
- Elastic IP(固定のグローバルIPアドレスを割り当てる機能)の理解と運用
- クラウド利用における基本的なコスト管理・請求確認の習慣

## 想定シナリオ(依頼内容)

クライアントから次のような依頼を受けました。

> 「クラウド上に検証用サーバーを1台構築し、自宅からリモートで安全に操作できるようにしてほしい。無料枠の範囲でよいので、まずは動作確認ができる環境を用意してほしい。」

社内に物理サーバーを置かず、必要なときだけクラウド上に検証環境を用意する、という近年よくあるニーズです。単にサーバーを立てるだけでなく、「安全に」という要望に応えるためのセキュリティ設定と、無料枠を超えて課金されないためのコスト意識が求められます。

## 事前準備・必要な環境

- [ ] AWSアカウント(クレジットカード情報と本人確認情報の登録が必要です)
- [ ] メールアドレスと携帯電話番号(SMS認証などに使用します)
- [ ] インターネットに接続されたPC(Windows/Mac/Linuxいずれでも可)
- [ ] SSHクライアント(Macは標準のターミナル、Windows 10/11は標準搭載のOpenSSHクライアントがあるのでPowerShellからsshコマンドがそのまま使えます。TeraTermなどのGUIツールでも構いません)
- [ ] 自分の自宅回線のグローバルIPアドレス(インターネット上で自分の回線を特定するための住所のようなIPアドレス)を確認する手段(検索エンジンで「自分のIP」などと調べれば確認できるサイトが多数あります)

> **注意**: AWSの無料利用枠は、対象サービスや期間、月間の利用時間上限などの条件が定められており、その内容は改定されることがあります。数年前までは「アカウント作成から12か月間」を軸にした枠組みが中心でしたが、新規アカウント向けの提供形態が見直された時期もあります。本ドキュメントに書かれている内容を鵜呑みにせず、**作業を始める前に必ず公式サイトの最新の無料利用枠ページで、対象サービス・条件・期間を確認**しておきましょう。

## 作業目的(ゴール)

- 無料枠対象のEC2インスタンスを1台起動する
- SSHでの接続元を自分のグローバルIPのみに制限し、安全な状態でリモート接続できるようにする
- Elastic IPを割り当て、インスタンスを再起動してもIPアドレスが変わらない状態にする
- 作業終了後、不要な課金が発生しないようリソースを整理する習慣を身につける

## 作業手順(詳細)

### 1. AWSアカウントの作成

公式サイトからアカウント登録を行います。クレジットカード情報の登録が必須である点、無料利用枠には条件があり超過分は課金される点を理解した上で進めましょう。

ルートユーザー(サインアップ時に作られる、すべての操作が可能な最上位の管理者アカウント)は日常作業には使わず、後々のためにIAM(AWSのユーザー管理サービス)で権限を絞った作業用ユーザーを作る運用が推奨されます。本案件ではまず全体の流れを体験することを優先し、ルートユーザーのまま進めますが、実務では避けるべき運用である点は覚えておいてください(詳しくは「振り返り・発展課題」で扱います)。

### 2. EC2インスタンスの起動

1. マネジメントコンソール右上のリージョン(AWSがサービスを提供するデータセンターの地理的なまとまり)選択から、自分に近いリージョン(例: 東京)を選ぶ
2. EC2のダッシュボードを開く
3. 「インスタンスを起動」を選択
4. AMI(Amazon Machine Image、OSやミドルウェアがセットになったテンプレート)を選択(Amazon LinuxなどFree tier対象と表記のあるものを選ぶ)
5. インスタンスタイプは無料枠対象(t2.microやt3.microなど、Free tier eligibleと表示があるもの)を選択
6. 新規キーペアを作成し、秘密鍵ファイル(.pem)をダウンロードする(このファイルは再ダウンロードできないため、大切に保管してください)
7. セキュリティグループを新規作成する(設定内容は次項で解説)
8. 内容を確認し、インスタンスを起動する

### 3. セキュリティグループの設定

セキュリティグループは、そのインスタンスに対する通信の許可ルールを定義するものです。SSH(Secure Shellの略、離れた場所にあるサーバーを安全に遠隔操作するための通信プロトコル)は通常ポート22番を使用します。このインバウンドルール(外部から内部への通信を許可する設定)は、必ず「自分のグローバルIPアドレス/32」のみを許可するように設定します。

| 項目 | 設定値 |
|---|---|
| タイプ | SSH |
| プロトコル | TCP |
| ポート範囲 | 22 |
| ソース | (自分のグローバルIP)/32 |

「/32」はCIDR(Classless Inter-Domain Routing、IPアドレスの範囲を「アドレス/桁数」の形式で表す表記法)という書き方で、「このIPアドレス1つだけ」を意味します。

**なぜ0.0.0.0/0(全世界からのアクセス許可)が危険なのか**: このソースを0.0.0.0/0にすると、世界中の誰でもそのポートに接続を試みることができる状態になります。実際に、公開直後のサーバーには自動化された不正ログイン試行が短時間で大量に届くことが知られています。パスワードや鍵の強度に関わらず、そもそも接続経路を自分だけに絞ることが最も効果的な防御になります。

### 4. 秘密鍵のパーミッション変更とSSH接続確認

ダウンロードした.pemファイルは、権限が緩いままだとSSHクライアントが「危険な鍵」と判断し、接続を拒否します。以下のコマンドで自分だけが読み取れる状態(400)に変更します。

```bash
chmod 400 my-key.pem
```

> **Windows(PowerShell)を使っている場合**: PowerShellには`chmod`コマンドが存在しないため、代わりに`icacls`コマンドで同等の設定を行います(WSLやGit Bashを使っている場合はLinuxと同様に`chmod`がそのまま使えます)。
>
> ```powershell
> icacls.exe my-key.pem /reset
> icacls.exe my-key.pem /grant:r "$($env:username):(r)"
> icacls.exe my-key.pem /inheritance:r
> ```

続けて、インスタンスに割り当てられたパブリックIPアドレス(インターネット経由で直接アクセスするためのIPアドレス。EC2コンソールのインスタンス詳細画面「パブリックIPv4アドレス」欄で確認できます)に対して接続します。

```bash
ssh -i my-key.pem ec2-user@<インスタンスのパブリックIP>
```

ユーザー名はAMIによって異なる点に注意してください。

| AMI | デフォルトユーザー名 |
|---|---|
| Amazon Linux 2 / Amazon Linux 2023 | ec2-user |
| Ubuntu | ubuntu |
| Debian | admin |

初回接続時はホスト鍵の確認メッセージが表示されるので、「yes」と入力して進めます。

### 5. Elastic IPの割り当て

EC2インスタンスは、停止・起動を行うとパブリックIPアドレスが変わってしまう場合があります。検証のたびに接続先IPが変わるのは不便で、DNS設定や他システムとの連携がある場合は特に困ります。Elastic IPは、アカウントに紐づく固定のグローバルIPアドレスをインスタンスに割り当てる機能で、これを使うことで再起動後もIPアドレスを維持できます。EC2ダッシュボードの「Elastic IP」からアドレスを確保し、対象インスタンスに関連付けます。

> **コスト面の注意**: かつては「Elastic IPをインスタンスに関連付けて使用中」であれば無料で、未使用のまま確保している場合だけ課金される仕組みでした。しかし2024年以降、AWSではEC2インスタンスに割り当てられたパブリックIPv4アドレス(Elastic IPかどうかを問わず)に対して、稼働中でも1時間あたりごく少額の課金が発生する料金体系に変わっています。無料利用枠だけではカバーしきれない場合があるため、**正確な最新の料金は公式サイトの料金ページで必ず確認**し、使わなくなったElastic IPは早めに関連付け解除・解放(リリース)する習慣をつけましょう。

### 6. コスト管理

作業を終えたら、検証用インスタンスは「停止」または「削除(終了)」します。停止しただけでもEBS(ストレージ)分の課金は継続する点に注意し、完全に不要であれば終了(Terminate)を選びましょう。

課金が発生しうるポイントは主に次の3つです。

- インスタンスの稼働時間(EC2)
- アタッチされているストレージ(EBS)
- 割り当てているパブリックIPv4アドレス(Elastic IP含む)

これらを頭に入れたうえで、AWSの請求ダッシュボードを定期的に確認し、想定外の課金が発生していないかチェックする習慣をつけます。

## 完了確認チェックリスト

- [ ] セキュリティグループのSSHが自分のグローバルIPのみに絞られている
- [ ] 秘密鍵ファイルのパーミッションが400になっている(Windowsの場合はicaclsで同等の設定がされている)
- [ ] 秘密鍵を指定してSSH接続ができる
- [ ] Elastic IPを割り当て、再起動後もIPが変わらないことを確認した
- [ ] 作業終了後、不要なインスタンス・Elastic IPを停止/削除した
- [ ] 請求ダッシュボードで想定外の課金がないか確認した

## よくあるエラーと対処法

| 症状 | 主な原因 | 対処法 |
|---|---|---|
| SSH接続がタイムアウトする | セキュリティグループでSSH(22番)が許可されていない、または自分のIPが変わっている | セキュリティグループのインバウンドルールを見直し、現在の自分のグローバルIPを再確認して設定し直す |
| `Permission denied (publickey)` と表示される | 指定した鍵ファイルが違う、または対応するユーザー名が誤っている | キーペア名とAMIごとのデフォルトユーザー名(ec2-userなど)を確認する |
| `WARNING: UNPROTECTED PRIVATE KEY FILE!` と表示され接続を拒否される | 秘密鍵ファイルのパーミッションが緩い(誰でも読める状態) | Mac/Linuxは`chmod 400 my-key.pem`、Windowsは`icacls`コマンドでパーミッションを修正する |
| 数日後に想定外の請求が来ていた | インスタンスやElastic IPを削除・解放し忘れていた、またはパブリックIPv4アドレスの稼働時間分の課金を見落としていた | 請求ダッシュボードを定期チェックし、不要なリソース(インスタンス・EBS・Elastic IP)は都度整理する運用を徹底する |

## 覚えておきたいポイント(暗記のコツ)

**1. 「クラウドは使ったら止める/消す」を出口の作業とセットで覚える**

クラウドのリソースは「使った分だけ料金が発生するレンタルスペース」だとイメージしましょう。部屋を借りたまま鍵を返さずに放置すると、実際には使っていなくても賃料が発生し続けるのと同じで、停止・削除(=退去手続き)まで完了して初めて課金が止まります。**「作る」だけでなく「出口(停止・削除・解放)まで含めて一つの作業」**と意識することが、クラウドエンジニアとしての基本的な金銭感覚につながります。

**2. `chmod 400` の数字の意味を分解して覚える**

| 桁 | 対象 | 400の値 | 意味 |
|---|---|---|---|
| 1桁目 | 所有者(自分) | 4 | 読み取りのみ可 |
| 2桁目 | グループ | 0 | 権限なし |
| 3桁目 | その他 | 0 | 権限なし |

パーミッションの数字は「読み取り=4、書き込み=2、実行=1」の合計で決まります。「400」は「自分だけが読める、それ以外は何もできない」状態だと覚えると、他の数字(例: 644や755)に出会ったときにも応用できます。

**3. CIDR表記は「数字が大きいほど範囲が狭い」と覚える**

- `0.0.0.0/0` → 条件なし = 全世界(危険)
- `自分のIP/32` → 32ビットすべて指定 = この1台だけ(安全)

0に近いほど範囲が広く、32に近いほど範囲が狭くなる、という関係を覚えておくと、他のCIDR表記(例: `/24`で256個のアドレス範囲)にも応用できます。セキュリティグループの設定に迷ったら、「まず自分のIPだけに絞り、必要になったら範囲を広げる」という順番で考える癖をつけましょう。

## 振り返り・発展課題

- なぜルートユーザーではなく、IAMで作業用ユーザーを作って運用することが推奨されるのか調べてみましょう
- 自宅回線のグローバルIPアドレスは固定ではない場合があります。IPアドレスが変わった際にセキュリティグループを更新し忘れるとどうなるか、実際に体験して考えてみましょう
- 発展課題として、パスワード認証を無効化しSSH鍵認証のみを許可する設定や、SSHのデフォルトポート(22番)を変更する方法を調べて試してみましょう
- AWS Budgets(予算アラート機能)を設定し、一定額を超えたらメール通知が届く仕組みを構築してみましょう
- AWSの無料利用枠や料金体系(特にパブリックIPv4アドレスの課金ルール)は時期によって変わります。本ドキュメントの内容と最新の公式情報を照らし合わせ、変更点がないか調べる習慣をつけましょう

## ポートフォリオへの書き方例

> **AWS無料枠を用いたクラウド検証環境の構築**
> AWS EC2上に検証用サーバーを1台構築し、セキュリティグループによるSSHアクセス制限(自分のグローバルIPのみ許可)、SSH鍵認証によるログイン、Elastic IPによる固定IP運用までを実施。クラウド利用時のコスト管理(不要リソースの停止・削除、パブリックIPアドレスの課金確認、請求ダッシュボードの確認)まで含めた一連の運用フローを体験し、セキュアな検証環境構築の基礎を習得しました。
