# 案件07: 仮想化環境構築案件(VirtualBox)

## 案件カテゴリ
仮想化基盤構築(検証・学習環境構築) / 難易度: 初級

サーバー構築エンジニアの現場では、本番環境にいきなり手を出す前に「仮想化ソフト」を使った検証環境で操作を練習してから作業するのが基本です。この案件はその土台となる、無料の仮想化ソフト「VirtualBox」を使った検証用サーバー環境構築の練習です。

## この案件で身につくスキル
- 仮想化(1台の物理パソコンの中に、複数の仮想的なパソコンを作り出す技術)の基本的な仕組みの理解
- VirtualBoxを使った仮想マシン(仮想的に作られたコンピューター。以下VM)の新規作成手順
- ホストPC(VirtualBoxを動かす元のパソコン)のスペックに応じたメモリ・ディスク割り当ての考え方
- ネットワークアダプタ(VMをネットワークにつなぐための仮想的な部品)の種類ごとの使い分け
- スナップショット(ある時点のVMの状態を丸ごと保存する機能)を使った安全な検証運用
- Guest Additions(VM内で動くOS=ゲストOSに追加でインストールする拡張ツール)導入による操作性向上

## 想定シナリオ(依頼内容)
> 「自宅の学習環境として、本番機に影響を与えずに何度でもやり直せる検証用サーバー環境を作りたいです。壊れてもすぐに元の状態に戻せるようにしておきたいので、その仕組みも含めて構築してもらえますか?」

これは架空のクライアントからの依頼という体裁ですが、実際には自分自身のパソコンの中に「何度失敗してもいいサーバー」を作る、という自己学習用の設定です。今後の案件(Linuxサーバー構築やネットワーク設定など)は、すべてこの仮想環境の上で練習していくことになるため、最初にしっかり土台を固めておきましょう。

## 事前準備・必要な環境

VirtualBoxを使うには、ホストPCのCPUが「仮想化支援機能」に対応している必要があります。これはCPUが仮想マシンを効率よく動かすための補助機能で、IntelのCPUでは「VT-x」、AMDのCPUでは「AMD-V」と呼ばれます。この機能がホストPCに搭載されており、かつBIOS/UEFIで有効になっていることが、VirtualBoxを動かすための大前提になります。

### ホストPCの推奨スペック目安
| 項目 | 最低ライン | 快適に動かすなら |
|---|---|---|
| CPU | 仮想化支援機能(Intel VT-x または AMD-V)に対応 | 4コア以上 |
| メモリ(RAM) | 8GB | 16GB以上 |
| ディスク空き容量 | 30GB以上 | 60GB以上(複数VM運用の場合) |

- [ ] ホストPCのCPUが仮想化支援機能に対応しているか確認した(具体的な確認方法は手順1で紹介します)
- [ ] VirtualBoxの入手方法を確認した(公式サイトから、利用しているOS向けのインストーラーを入手します。詳しい流れは手順2で解説します)
- [ ] 仮想マシンにインストールするOSのインストールメディア、ISOファイル(CDやDVDの中身を1つのファイルにまとめた形式)などを用意した(学習用途では無料で使えるLinuxディストリビューションがおすすめです)

## 作業目的(ゴール)
- ホストPCに影響を与えない、独立した検証用サーバー(VM)を1台構築する
- 用途に応じたネットワークアダプタを選択できるようになる
- スナップショットを使い、「壊れたらすぐ戻せる」安心な検証習慣を身につける
- Guest Additionsを導入し、日々の検証作業を快適に行えるようにする

## 作業手順(詳細)

### 手順1: BIOS/UEFIで仮想化支援機能を確認する
VirtualBoxで快適にVMを動かすには、ホストPCのCPUが持つ仮想化支援機能(Intel VT-x/AMD-V)が、BIOS(パソコン起動時にハードウェアを制御する基本プログラム)またはUEFI(BIOSに代わる新しいファームウェア規格で、同様に起動前の設定画面を持ちます)で有効になっている必要があります。パソコン起動直後にメーカー指定のキー(F2やDeleteキーなど)を押してBIOS/UEFI画面に入り、「Virtualization Technology」や「SVM Mode」といった項目が有効(Enabled)になっているか確認しましょう。

**コラム: BIOS画面に入らずに確認する方法**

毎回BIOS画面に入るのが手間な場合、OS上のコマンドである程度の見当をつけることもできます。あくまで簡易チェックなので、最終的にVMが起動しない場合はBIOS/UEFIでの確認を優先してください。

Windowsの場合(コマンドプロンプトまたはPowerShellで実行):
```powershell
systeminfo | findstr /I "Virtualization"
```
「Virtualization Enabled In Firmware」の行が「Yes」になっていれば、仮想化支援機能が有効な状態です。

Linuxの場合:
```bash
egrep -c '(vmx|svm)' /proc/cpuinfo
```
0より大きい数字が表示されれば、CPUが仮想化支援機能に対応しています(数字はCPUコア数などにより変わります)。

### 手順2: VirtualBoxをインストールする
公式サイトから、自分のOS(Windows/macOS/Linuxなど)に対応したインストーラーを入手し、画面の指示に従ってインストールします。特別なオプションを触る必要はなく、基本的にはデフォルト設定のまま進めて問題ありません。

### 手順3: 新規仮想マシンを作成する
VirtualBoxを起動し、「新規」ボタンから仮想マシン作成ウィザードを開始します。大まかな流れは次のとおりです。

1. 名前を入力する(例: verify-server-01)
2. インストールするOSの種類とバージョンを選択する
3. メモリサイズを割り当てる
4. 仮想ハードディスクを新規作成する

**メモリサイズの考え方**

| ホストPCの搭載メモリ | VMへの割り当て目安 |
|---|---|
| 8GB | 2GB程度(ホスト側の動作を圧迫しないよう控えめに) |
| 16GB | 4GB程度 |
| 32GB以上 | 8GB程度(複数VM同時起動も視野に) |

考え方のポイントは「ホストPCが普段どおり動くための余力を必ず残す」ことです。VMにメモリを割り当てすぎると、ホストPC自体の動作が重くなってしまいます。

**ディスクサイズの考え方**

学習用のLinuxサーバーであれば20GB〜40GB程度を目安に、「可変サイズ(実際に使用した分だけディスク容量を消費していく形式)」で作成するのがおすすめです。最初から「固定サイズ」で大きく確保すると、ホストPCのディスクをいきなり圧迫してしまうためです。

### 手順4: ネットワークアダプタを設定する
VM作成後、設定画面の「ネットワーク」タブでアダプタの種類を選びます。用途によって最適な種類が異なるため、下記の表で違いを理解しておきましょう。

| 種類 | 特徴 | こんな時に使う |
|---|---|---|
| NAT | VMからは外部(インターネット)に接続できるが、外部やホスト、他のVMからはVMに直接アクセスしにくい | 単体のVMでとりあえずインターネットに繋ぎたい時、初期構築時のパッケージ更新など |
| ホストオンリーアダプタ | ホストPCと仮想的な専用ネットワークでのみ繋がる。インターネットには出られない | ホストPCから複数VMへSSH接続(ネットワーク越しに他のコンピューターを遠隔操作するための仕組み)したい時、外部に絶対出したくない閉じた検証をしたい時 |
| ブリッジアダプタ | VMが物理的なLANに直接参加し、あたかも同じネットワーク上の別マシンのように振る舞う | 家庭内の他の端末からVMへ直接アクセスしたい時、本番に近いネットワーク構成を試したい時 |

学習の初期段階では「NAT」でインターネットからパッケージを取得しつつ、「ホストオンリーアダプタ」を追加してホストPCからSSH接続する、という2枚構成が使いやすくおすすめです。

### 手順5: ゲストOSをインストールする
用意したISOファイルをVMの光学ドライブに割り当てて起動し、通常のOSインストール手順に従って進めます。この部分は物理的なパソコンにOSをインストールする手順とほぼ同じです。

### 手順6: Guest Additionsを導入する
ゲストOSのインストールが終わったら、VMウィンドウ上部のメニューから「デバイス」→「Guest Additions CDイメージの挿入」を選択し、ゲストOS内でインストーラーを実行します。これにより次のような操作が快適になります。

- ホストPCとVMのウィンドウサイズに合わせて自動で画面解像度が調整される
- ホストPCとVM間でクリップボード(コピー&ペースト)を共有できる
- 共有フォルダ機能(ホストPC上の特定フォルダをVMからも読み書きできるようにする機能)が使えるようになる

**Linuxゲストの場合の注意点**

Linuxディストリビューションでは、Guest Additionsのインストールに必要なビルド用ツール(コンパイラやカーネルヘッダー)が最初から入っていないことがあります。CDを挿入する前に、あらかじめ次のようなコマンドで準備しておくとスムーズです(Ubuntu/Debian系の例)。

```bash
sudo apt update
sudo apt install -y build-essential dkms linux-headers-$(uname -r)
```

自動実行のダイアログが出ない場合は、次のようにCDイメージを手動でマウントしてインストーラーを実行することもできます。

```bash
sudo mount /dev/cdrom /mnt
sudo /mnt/VBoxLinuxAdditions.run
```

必須ではありませんが、日々の作業効率が大きく変わるため、導入しておくことを強くおすすめします。

### 手順7: 初期構築直後にスナップショットを取得する
すべての設定が終わり、ゲストOSが問題なく起動する状態になったら、VirtualBoxマネージャーの「スナップショット」機能で現在の状態を保存します。これは「何かあったらここまで戻る」という復元ポイントです。

以降、パッケージ(ソフトウェアをインストール・更新するためのひとまとまりのデータ)のアップデートや新しいソフトの導入など、何か大きな変更を加える前には必ずスナップショットを取得する習慣をつけましょう。万が一操作を誤って環境を壊してしまっても、スナップショットから数分で元の状態に復元できます。

## よくあるエラーと対処法

| 症状 | 原因 | 対処法 |
|---|---|---|
| VMを起動すると「VT-x/AMD-Vが有効になっていません」というエラーが出て起動しない | BIOS/UEFIで仮想化支援機能が無効になっている | パソコンを再起動してBIOS/UEFI画面に入り、Virtualization TechnologyやSVM Modeの項目を有効(Enabled)に変更して保存する |
| NAT設定のままだと、他のVMやホストPCの外部から接続できず戸惑う | NATはVMから外への通信を優先する設定で、外部からVMへの直接アクセスを想定していない | VM同士やホストPCからアクセスしたい場合は、ホストオンリーアダプタまたはブリッジアダプタを追加で有効にする |
| ゲストOSの画面が小さいまま拡大できない | Guest Additionsが未導入、または導入に失敗している | Guest Additions CDイメージを挿入し直し、ゲストOS内でインストーラーを実行し、完了後にVMを再起動する |
| Linuxゲストで、Guest Additionsのインストール自体が「カーネルヘッダーが見つかりません」等のエラーで失敗する | ビルドに必要なパッケージ(コンパイラやカーネルヘッダー)が事前にインストールされていない | `build-essential`、`dkms`、`linux-headers-$(uname -r)` などのパッケージを導入してから、インストーラーを再実行する |
| スナップショットを取得しようとするとエラーになる、または極端に時間がかかる | ホストPCのディスク空き容量が不足している | 不要なスナップショットを削除する、またはホストPCのディスク容量を確保してから再実行する |

## 覚えておきたいポイント(暗記のコツ)

**その1: スナップショットの合言葉**

検証環境を使ううえで最も大事な習慣は、たった一行のルールにまとめられます。

> **「何か作業する前にスナップショット」**

新しいコマンドを試す前、設定ファイルを書き換える前、パッケージをアップデートする前。「これから何かする」と思ったその瞬間にスナップショットを取る癖をつけておけば、失敗を恐れずに何度でも挑戦できます。検証環境の一番の価値は「気軽に壊せること」であり、その価値を最大限引き出すのがスナップショットです。

**その2: ネットワークアダプタは「たとえ話」で覚える**

3種類の違いが混同しやすいときは、次の例えで整理すると覚えやすくなります。

| 種類 | 覚え方のたとえ |
|---|---|
| NAT | 「一方通行の玄関」。自分(VM)から外へは出かけられるが、外から勝手に訪ねて来ることはできない |
| ホストオンリーアダプタ | 「家族専用の内線電話」。ホストPCとVMの間だけでつながり、外の世界(インターネット)には出られない |
| ブリッジアダプタ | 「表通りに直接面した玄関」。LAN上の他の端末と対等な立場でつながる |

**その3: VT-xとAMD-Vはメーカー名がそのまま入っている**

「Intelの仮想化技術=VT-x」「AMDの仮想化技術=AMD-V」と覚えれば、BIOS画面でどちらの項目を探せばよいか迷いません。

## 振り返り・発展課題
本案件で作成したVMは、今後のさまざまなサーバー構築案件の土台になります。慣れてきたら、次のような発展的な構成にも挑戦してみましょう。

- ホストオンリーアダプタを使い、複数のVM同士だけで通信できる小さな検証ネットワークを組んでみる
- Webサーバー用VMとデータベース用VMを分けて作成し、2台構成のシステムを疑似的に再現してみる
- スナップショットを複数回取得し、名前や取得日時を整理しながら「どの時点にどんな状態を保存したか」を管理する練習をする
- VMのクローン機能を使い、1台構築したVMを複製して同じ設定のサーバーを素早く増やす方法を試す
