## 想定シナリオ(依頼内容)
お客様の情報システム部門から、次のような依頼が届いたと想定します。

> 「4月の人事異動で、営業部の山田太郎さんが総務部に異動しました。ADのユーザー情報を総務部のOUに移動し、営業部の共有フォルダへのアクセス権を持つグループから外して、総務部のグループに追加してください。あわせて、新入社員の佐藤花子さんのアカウントも総務部OUに新規作成をお願いします。」

このように、AD管理者には「ユーザー情報の異動」「グループ所属の付け替え」「新規アカウント作成」がセットで依頼されることが非常に多く、実務でも頻出のタスクです。今回は、この一連の作業を安全かつ正確にこなせるようになることを目指します。

なお、本案件は「案件07: 仮想環境構築」で作成したWindows Server評価版+ADドメインサービス(AD DS。ADの機能をサーバーに追加するための「役割」の名前です)の検証環境がすでに構築済みであることを前提とします。まだの場合は、先に案件07を参考に環境を用意してください。

## 作業手順(詳細)

### 1. Active Directoryの基本構造を理解する
ADは「組織の人・モノを一元管理する台帳システム」とイメージするとわかりやすいです。全体の関係は次のようになっています。

```text
ドメイン(組織全体の管理単位。例: example.local)
 ├─ OU: 営業部
 │    └─ ユーザー: 山田太郎
 ├─ OU: 総務部
 │    └─ ユーザー: 佐藤花子
 ├─ グループ: 営業部_共有フォルダ(役割ごとの名簿。アクセス権をまとめて管理するために使う)
 └─ グループ: 総務部_共有フォルダ
```

- **ドメイン**:管理の最上位の箱。会社全体に相当します。
- **OU**:ドメインの中の仕切り。部署や拠点ごとに分けるのが一般的です。1人のユーザーが所属できるOUは基本的に1つだけです。
- **ユーザー**:社員一人ひとりに対応するアカウント(ログイン情報)。
- **グループ**:複数のユーザーをまとめた名簿。フォルダのアクセス権やアプリの利用権限をグループ単位で割り当てることで、管理の手間を減らせます。1人のユーザーが複数のグループに同時に所属することができます。

> **初心者がつまずきやすいポイント**: OUとグループはどちらも「ユーザーをまとめる箱」に見えるため混同しがちですが、役割はまったく別物です。**OUは「住所」(1人1つだけ)、グループは「役割の名札」(いくつでも身につけられる)** とイメージすると整理しやすくなります。OUは主にグループポリシー(端末やユーザーに一括で設定を適用する仕組み)の適用範囲を決めるため、グループは主にファイルやアプリへのアクセス権を決めるために使う、と覚えておきましょう。

なお、上の図はグループをドメイン直下に置いていますが、実際の現場では専用の「Groups」OUや既定の「Users」コンテナにまとめて格納することも多くあります。今回は説明をシンプルにするため、部署OUのすぐ隣に配置したイメージで描いています。

### 2. OU設計の考え方
OUは「組織図に合わせて部署ごとに分ける」のが基本の考え方です。

| OU名 | 目的 |
|---|---|
| 営業部 | 営業部のユーザー・パソコンをまとめる |
| 総務部 | 総務部のユーザー・パソコンをまとめる |
| IT部門 | 情報システム部門の管理者アカウントなど |

部署ごとにOUを分けておくと、「このOU配下だけにグループポリシーを適用する」といった柔軟な運用ができるようになります。今回のシナリオでは、山田さんを「営業部OU」から「総務部OU」へ移動する作業がこれにあたります。

### 3. 演習用の初期データを準備する(下準備)
まっさらな検証環境には、まだ「営業部」「総務部」OUも、共有フォルダ用のグループも存在しません。本題の異動作業に入る前に、シナリオの前提となるデータをPowerShellでまとめて作っておきましょう(GUIでも、OUを右クリック→「新規作成」→「組織単位」/「グループ」から同様の操作が可能です)。

```powershell
# 部署ごとのOUを作成(すでに存在する場合はエラーになります)
New-ADOrganizationalUnit -Name "営業部" -Path "DC=example,DC=local"
New-ADOrganizationalUnit -Name "総務部" -Path "DC=example,DC=local"

# 共有フォルダのアクセス権を管理するためのセキュリティグループを作成
New-ADGroup -Name "営業部_共有フォルダ" -GroupScope Global -GroupCategory Security -Path "OU=営業部,DC=example,DC=local"
New-ADGroup -Name "総務部_共有フォルダ" -GroupScope Global -GroupCategory Security -Path "OU=総務部,DC=example,DC=local"

# 異動前の状態を再現するため、山田太郎さんを営業部OUに作成し、営業部グループに所属させておく
New-ADUser -Name "山田太郎" `
  -GivenName "太郎" -Surname "山田" `
  -SamAccountName "yamada.taro" `
  -UserPrincipalName "yamada.taro@example.local" `
  -Path "OU=営業部,DC=example,DC=local" `
  -AccountPassword (ConvertTo-SecureString "P@ssw0rd2024!" -AsPlainText -Force) `
  -Enabled $true -ChangePasswordAtLogon $true

Add-ADGroupMember -Identity "営業部_共有フォルダ" -Members "yamada.taro"
```

- `-SamAccountName` は、Windowsの下位互換のために使われる短いログオン名です。社内システムのログインIDとして使われることも多い項目です。
- 既定では作成したOUに「誤って削除しないよう保護する」設定が有効になっています。検証をやり直すためにOUを削除したくなった場合は、ADUCでOUのプロパティを開き「オブジェクトを誤って削除されないように保護する」のチェックを外してから削除してください。

これで、依頼が来る前の状態(山田さんが営業部に所属している状態)を再現できました。ここからが本題の作業です。

### 4. パスワードポリシーの基本を確認する
ユーザー作成の前に、AD既定の「デフォルトドメインポリシー」で設定されているパスワードポリシーを確認しておきましょう。ここを知らずに作業すると、次の手順でユーザー作成に失敗しやすくなります。

| 項目 | 内容 |
|---|---|
| 複雑性の要件 | 英大文字・英小文字・数字・記号のうち3種類以上を組み合わせる |
| 最小文字数 | 既定では7文字以上(組織により変更可能) |
| パスワード履歴 | 既定では過去24世代分のパスワードの再利用を禁止 |
| 最大有効期間 | 既定では42日ごとにパスワード変更を要求 |

これらはグループポリシー管理コンソール(GPMC。グループポリシーの内容を作成・編集・確認するための管理ツール)を開き、「Default Domain Policy」を編集することで確認・変更できます。

**暗記のコツ**: 既定値は「複雑性3種類・最短7文字・有効期限42日」なので、「3・7・42」という数字の並びとして覚えておくと、現場でとっさに思い出しやすくなります。

### 5. GUIでの操作(Active Directory ユーザーとコンピューター)
1. DCにログインし、サーバーマネージャーまたは「ファイル名を指定して実行」から `dsa.msc` を起動して、ADUCを開きます。
2. **新規ユーザー作成(佐藤花子さんの例)**
   - 「総務部」OUを右クリック→「新規作成」→「ユーザー」を選択します。
   - 姓・名を入力し、ログオン名(ユーザーがログインに使う名前。多くの場合UPN〈ユーザープリンシパル名〉の形式で、`ユーザー名@ドメイン名` のようにメールアドレスに似た形になります)を入力します。例: `sato.hanako@example.local`
   - 初期パスワードを設定し、「次回ログオン時にパスワードの変更を要求する」にチェックを入れます。手順4で確認したパスワードポリシーを満たすパスワードを設定しましょう。
3. **ユーザーの異動(山田さんの例)**
   - 「営業部」OU内の「山田太郎」を右クリック→「移動」を選択します。
   - 移動先として「総務部」OUを選び、OKをクリックします。
4. **グループ所属の変更**
   - 「山田太郎」のプロパティを開き、「所属するグループ」タブを開きます。
   - 「追加」ボタンから「総務部_共有フォルダ」グループを検索して追加します。
   - 続けて一覧から「営業部_共有フォルダ」グループを選択し、「削除」ボタンで外します。

### 6. PowerShellでの操作(参考)
GUIと同じ操作は、PowerShellのADモジュールを使ってコマンドでも実行できます。日々同じ作業を繰り返す場合は、こちらの方が正確かつ効率的です。以下では、山田さんのSamAccountNameを `yamada.taro`(手順3で作成済み)として進めます。

```powershell
# 新規ユーザー作成(佐藤花子さん)
New-ADUser -Name "佐藤花子" `
  -GivenName "花子" -Surname "佐藤" `
  -SamAccountName "sato.hanako" `
  -UserPrincipalName "sato.hanako@example.local" `
  -Path "OU=総務部,DC=example,DC=local" `
  -AccountPassword (ConvertTo-SecureString "P@ssw0rd2024!" -AsPlainText -Force) `
  -Enabled $true -ChangePasswordAtLogon $true

# ユーザー情報の確認(所属グループとDN〈Distinguished Name。組織内での位置を示す住所のような文字列〉を表示)
Get-ADUser -Identity "yamada.taro" -Properties MemberOf, DistinguishedName

# グループへの追加
Add-ADGroupMember -Identity "総務部_共有フォルダ" -Members "yamada.taro"

# 旧グループからの削除
Remove-ADGroupMember -Identity "営業部_共有フォルダ" -Members "yamada.taro" -Confirm:$false
```

OU間の異動はGUIの「移動」に相当する `Move-ADObject` を使うと自動化できます。あわせて覚えておくと便利です。

```powershell
Get-ADUser -Identity "yamada.taro" | Move-ADObject -TargetPath "OU=総務部,DC=example,DC=local"
```

> **安全に試すコツ**: `Remove-ADGroupMember` のような削除系コマンドは、末尾に `-WhatIf` を付けて一度実行すると、実際には変更を加えずに「何が起きるか」だけを確認できます。操作に慣れるまでは `-WhatIf` で予行演習してから、`-Confirm:$false` を付けた本番実行に進むと安心です。

## よくあるエラーと対処法

| エラー・症状 | 原因 | 対処法 |
|---|---|---|
| ユーザー作成時に「ユーザー名の形式が正しくありません」と表示される | UPNの形式が `ユーザー名@ドメイン名` になっていない(記号ミスや全角文字混入など) | UPNは半角英数字と `.`(ピリオド)`@` のみで構成し、命名規則に沿って入力し直す |
| ユーザー作成時にパスワードエラーで失敗する | パスワード複雑性の要件(3種類以上の文字種)を満たしていない、または最小文字数(既定7文字)を下回っている | 大文字・小文字・数字・記号を組み合わせた8文字以上のパスワードに変更する |
| グループを変更した直後、共有フォルダへのアクセス権がすぐに反映されない | Kerberos認証のチケット(ログイン時に発行される、権限情報を含む「通行証」のようなもの)には、ログオン時点のグループ情報が記録されており、ログオフ・再ログオンしないと更新されないため | 対象ユーザーに一度サインアウト→再サインインしてもらう。すぐに確認したい場合は、コマンドプロンプトで `klist purge` を実行してKerberosチケットのキャッシュを破棄し、再取得させる方法もある |
| グループポリシーに基づく設定(ログオンスクリプトやドライブの自動割り当てなど)がすぐに反映されない | グループポリシーの適用にはタイムラグがあり、既定ではバックグラウンド更新の間隔が90分(0〜30分のランダムなずれつき)に設定されているため | すぐに反映させたい場合は、対象端末で `gpupdate /force` を実行してグループポリシーを即時再適用する |
| ADUCで移動したはずのユーザーが元のOUに表示され続ける | 管理画面の表示が更新されていないだけのケースが多い | ADUCの表示を更新(F5キーまたは更新ボタン)する |

## 覚えておきたいポイント(暗記のコツ)
1. **「追加」と「削除」は必ずセットで行う**:AD管理でグループ所属を変更するときは、**「追加(所属させる)」と「削除(外す)」を必ずセットで行う**、と覚えておきましょう。新しいグループに追加しただけで古いグループからの削除を忘れると、「異動したのに前の部署のフォルダにもアクセスできてしまう」という権限の残留(セキュリティ上のリスクにもなります)が発生します。人事異動の依頼が来たら、まず「追加すべきグループ」と「削除すべきグループ」を紙やメモに書き出してから作業する習慣をつけると、作業漏れを防げます。
2. **OUとグループの役割の違い**:「OUは住所(1人1つ)、グループは役割の名札(いくつでも)」と覚えておくと、「今回変えるのはOU(所属部署)なのか、グループ(アクセス権)なのか、それとも両方なのか」を作業前に整理しやすくなります。
3. **パスワードポリシーの既定値は「3・7・42」**:複雑性3種類・最小文字数7文字・有効期限42日という数字の並びで覚えておくと、ユーザー作成時のパスワードエラーにもすぐ気づけます。

- 「異動によりアクセス権が残ってしまう」リスクについて、なぜセキュリティ上問題なのかを自分の言葉でまとめてみると理解が深まります。

## ポートフォリオへの書き方例
> **Active Directoryにおけるユーザー・グループ運用管理**
> 検証環境(Windows Server + AD DS)において、部署異動を想定したOU・セキュリティグループの設計、ユーザーアカウントの新規作成、OU間の異動、グループ所属変更(旧グループ削除・新グループ追加)を実施。ADUCによるGUI操作に加え、`New-ADOrganizationalUnit` `New-ADGroup` `New-ADUser` `Get-ADUser` `Add-ADGroupMember` `Remove-ADGroupMember` `Move-ADObject` などのPowerShellコマンドレットを用いた同等操作も習得。パスワードポリシーの要件や、Kerberos認証・グループポリシーそれぞれで生じる反映タイミングの違いを踏まえたトラブルシューティング経験あり。
