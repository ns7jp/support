# はじめての案件を始める前に

このガイドは、「ターミナルをほとんど使ったことがない」「何を記録すればよいかわからない」という方が、最初の案件を安全に始めるためのページです。すべてを暗記する必要はありません。わからなくなったら、このページへ戻って確認してください。

## まず確認すること

次の項目にチェックが付けば、学習を始められます。

- [ ] [`docs/02_environment-setup.md`](02_environment-setup.md) を読み、自分のPCが推奨スペックを満たすか確認した
- [ ] 大切なファイルをバックアップした
- [ ] 管理者権限が必要な操作と、通常の操作の違いを確認した
- [ ] 演習は会社や学校の本番環境ではなく、自分の検証用PCまたは仮想マシンで行う
- [ ] AWSを使う案件08では、予算通知を設定し、終了後にリソースを削除する

PC操作に不安がある場合は、最初から8週間プランに合わせなくても構いません。まず案件01だけを1週間かけて行い、「手順を読む → 操作する → 結果を確認する → 記録する」という流れに慣れましょう。

## コマンド例の読み方

コマンドは、PowerShell、コマンドプロンプト、Linuxのターミナルなど、案件で指定された画面に入力します。

```bash
ping <確認したいIPアドレス>
```

- `ping` は実際に入力するコマンドです。
- `<確認したいIPアドレス>` は説明用の仮の値です。山括弧ごと入力せず、自分の環境の値に置き換えます。例: `ping 192.168.1.1`
- コードブロックの上にある `$`、`>`、`PS C:\>` などの入力待ち記号が例に含まれている場合、その記号自体は入力しません。
- `#` から始まる行は多くのLinuxコマンド例では説明用のコメントです。ただし、管理者ユーザーの入力待ち記号として使われる場合もあるため、前後の説明を確認します。
- 実行結果は例と完全に同じでなくても構いません。ホスト名、IPアドレス、日時、OSのバージョンなどは環境によって変わります。

### 実行前の3点確認

コピーしてすぐに実行せず、次の3点を声に出して確認します。

1. **どこで**: Windows側か、Linux側か、接続先サーバー上か
2. **何を変えるか**: 表示だけか、設定・ファイル・ユーザーを変更するか
3. **戻せるか**: 元の値を記録したか、仮想マシンのスナップショットがあるか

`sudo`、ユーザー削除、ファイル削除、ファイアウォール、SSH設定を含む操作は特に注意してください。意味が説明できないコマンドは、実行前に用語集やコマンドのヘルプで確認します。パスワード、秘密鍵、個人情報、グローバルIPアドレスは作業ログやスクリーンショットに残さないでください。

## 1手順ごとの進め方

一度に案件全体を終わらせようとせず、各手順を次の小さなサイクルで進めます。

1. 手順の目的を1文で言い換える
2. 変更前の状態をメモする
3. コマンドまたはGUI操作を1つ実行する
4. 出力や画面を見て、成功したか確認する
5. 実行した内容と結果を作業ログに記録する
6. 問題がなければ次の操作へ進む

エラーが出た場合は、むやみに別のコマンドを試さず、エラーメッセージを記録します。「どの手順で」「何を実行し」「何が表示され」「直前に何を変更したか」の4点があると、原因を調べやすくなります。

## 最小限の作業ログ

案件ごとに自分の作業用フォルダーを作り、`notes.md`へ次の形式で記録します。教材本体を読んだだけでは成果物にならないため、**自分の環境で得た結果と自分の判断**を残すことが重要です。

```markdown
# 案件01 作業ログ

- 実施日: 2026-09-01
- 環境: Windows 11 / VirtualBox など
- 今日のゴール: PC名を規則どおりに変更し、再起動後に確認する

## 実施内容

1. 変更前のPC名を確認した
2. PC名を `TKY-SALES-001` に変更した
3. 再起動後に新しいPC名を確認した

## 結果

- 成功した確認項目:
- 発生したエラー:
- 原因と対処:
- 次回行うこと:
```

スクリーンショットを残す場合は、成功を示す箇所がわかる名前にします(例: `01-hostname-after-restart.png`)。公開前にユーザー名、メールアドレス、IPアドレス、ライセンス情報、秘密鍵などが写っていないか確認してください。

## つまずいたときの止まり方

次の順番で切り分けます。

1. 案件内の「よくあるエラーと対処法」を読む
2. エラーメッセージを省略せず確認する
3. OS、バージョン、実行したコマンド、期待した結果、実際の結果をメモする
4. 直前の変更を1つだけ戻す、またはスナップショットへ戻す
5. 解決しなければ、記録した情報を添えて詳しい人へ質問する

本番環境を使ってしまった、課金が続いている可能性がある、秘密鍵やパスワードを公開した可能性がある場合は、演習を続けず、まず利用停止や認証情報の変更を優先してください。

## 初心者向けの推奨順序

ファイル番号だけを見ると案件04を先に進めたくなりますが、案件04には仮想化環境が必要です。次の順序なら前提環境で迷いにくくなります。

```text
環境準備 → 01 → 02 → 03 → 07 → 04 → 05 → 06 → 08 → 09 → 10
```

案件09と10は、どちらを先に実施しても構いません。詳しい日程と案件同士の関係は [`docs/01_roadmap.md`](01_roadmap.md) を参照してください。

## 案件01へ進む前のミニ練習

最後に、変更を伴わない確認操作を1つ試します。

1. WindowsでPowerShellを開く
2. `hostname` を実行する
3. 表示されたPC名を作業ログに記録する
4. PowerShellを閉じる

「コマンドを実行し、結果を確認し、記録する」までできれば準備完了です。[案件01](../cases/case01_pc-setup.md)へ進みましょう。
