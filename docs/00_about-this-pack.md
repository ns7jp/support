# このパックについて

このドキュメントパックは、**未経験からサーバー構築エンジニアへの就職・転職**を目指す方のための、自習用ポートフォリオ教材です。ポートフォリオとは、実務経験の代わりに「自分はここまでできます」と面接や書類選考で提示するための成果物集のことです。

このパックでは、実際の職場で発生しそうな**案件**(上司やお客様から依頼される具体的な作業)を10本用意しました。1つずつ手を動かして取り組み、作業内容と結果をGit(誰が・いつ・何を変更したかを記録できるバージョン管理ツール)で記録していくことで、履歴書や職務経歴書にそのまま書ける「動くポートフォリオ」が完成する構成になっています。

## なぜ「案件」形式で学ぶのが効果的か

単に技術書を読んだり、コマンドをそのまま写経したりするだけでは、実務で本当に必要な力は身につきにくいものです。現場のヘルプデスク(利用者からの問い合わせ対応窓口)やインフラ運用の仕事は、多くの場合次のような流れで進みます。

**依頼を受ける → 状況を確認する → 原因を切り分ける(問題の発生箇所を絞り込むこと) → 対応する → 結果を報告する**

このパックでは、それぞれの案件を実際の依頼書のような形式で提示し、あなた自身にこの流れを疑似体験してもらいます。これにより、次の3つの力を同時に鍛えることができます。

| 身につく力 | 内容 |
|---|---|
| 手順書作成力 | 誰が読んでも再現できる作業手順をまとめる力 |
| 切り分け力 | トラブルの原因を論理的に絞り込んでいく力 |
| 報告力 | 対応結果や学んだことを分かりやすく伝える力 |

これらはすべて、実際の面接で「何ができるか」を具体的に語るための材料になります。

> **暗記のコツ**:「受付 → 確認 → 切り分け → 対応 → 報告」の5ステップは、全10案件で繰り返し登場する型です。案件に取り組むたびに「今どのステップにいるか」を声に出して確認する習慣をつけると、暗記しようとしなくても自然に体で覚えられます。

## 想定する対象者

このパックは、次のような方を想定して作られています。

- IT実務未経験だが、サーバー構築・インフラ運用の仕事に興味がある方
- 独学でインフラ/サーバーエンジニアを目指している方
- 職業訓練校やスクールに通っており、演習用の実践課題を探している方
- ITパスポート程度の基礎知識はあるが、実機操作の経験がまだ少ない方

前提知識としてITパスポート程度の用語理解があれば十分です。専門用語は各ドキュメント内で都度補足しますので、安心して取り組んでください。

> **暗記のコツ**: 10案件は、①ヘルプデスク基礎(case01〜03)②サーバー構築(case04〜07)③クラウド・運用・セキュリティ(case08〜10)の3グループに分けて覚えると、全体像を把握しやすくなります。「まず窓口対応、次にサーバーそのものを作る、最後に運用・守る」という順番でイメージしてみてください。

## 各案件ドキュメントの共通フォーマット

すべての案件ドキュメントは、以下の11セクションという統一フォーマットで書かれています。

| # | セクション | 内容 |
|---|---|---|
| 1 | 案件カテゴリ | 分野・技術領域の分類 |
| 2 | この案件で身につくスキル | 取り組むことで得られる知識・操作の一覧 |
| 3 | 想定シナリオ(依頼内容) | 依頼者から届いた相談内容(依頼書のような文面) |
| 4 | 事前準備・必要な環境 | 必要な環境やソフトウェア |
| 5 | 作業目的(ゴール) | この案件で目指す状態 |
| 6 | 作業手順(詳細) | 実際に打つコマンド・操作 |
| 7 | 完了確認チェックリスト | 完了したと言えるかどうかの確認項目 |
| 8 | よくあるエラーと対処法 | つまずきやすい落とし穴とその直し方 |
| 9 | 覚えておきたいポイント(暗記のコツ) | 記憶に残すための語呂合わせ・整理の仕方 |
| 10 | 振り返り・発展課題 | 学んだ知識の整理と、次に挑戦したいこと |
| 11 | ポートフォリオへの書き方例 | 職務経歴書・GitHub(ソースコードや作業記録を保存・公開できるサービス)用の文例 |

この形式が全案件で統一されているため、1件目で流れを理解してしまえば、2件目以降は「今どこを読んでいるか」に迷うことなく、スムーズに読み進められます。

> **暗記のコツ**: 11個をひとつずつ覚えようとせず、①状況把握(1〜4:何を・どんな状態で頼まれたか)②実施(5〜8:どう対応し、どう確認するか)③まとめ(9〜11:何を学び、どう伝えるか)の3つの塊で捉えると、次に読む・書くセクションが感覚的にわかるようになります。

## 使い方の流れ

- [ ] 1. `docs/02` の環境準備ドキュメントを読み、演習用の環境(仮想マシン〈1台のPCの中に複数のPC環境を作れる技術〉など)を用意する
- [ ] 2. `docs/03` の初心者向けスタートガイドを読み、コマンド例の読み方、安全確認、作業ログの残し方を確認する
- [ ] 3. `docs/01` の学習ロードマップを読み、自分のペースで取り組む順番・スケジュールを決める
- [ ] 4. `cases/` フォルダの案件をロードマップの推奨順序で実施し、区切りごとにGitへコミットする
- [ ] 5. `docs/91` を参考に、取り組んだ案件をポートフォリオとして文章にまとめる

コミットの例は次のようなイメージです。

```bash
git add cases/case01
git commit -m "case01: PC初期セットアップ対応 完了"
```

このようにコミットを積み重ねていくことで、取り組みの過程そのものが学習履歴として残り、面接で「継続して努力できる人材である」ことを示す材料にもなります。焦らず、1件ずつ着実に進めていきましょう。
