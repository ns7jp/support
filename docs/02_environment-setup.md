# 演習環境の準備

この教材の演習では、仮想化ソフト(1台の物理的なパソコンの中に、複数の仮想的なコンピューター「仮想マシン」を作って動かす技術)を使い、実際に手を動かしてサーバーを構築し、動作を確認しながら学んでいきます。演習を始める前に、仮想化ソフトを実際に動かす物理PC本体(以下「ホストPC」)の環境をきちんと整えておくことが、後々のトラブルを減らす一番の近道です。この記事では、演習に必要なPCスペックの目安から、VirtualBoxの導入とネットワークの基礎、OSイメージの入手方法、AWSアカウントの準備、そして安全に演習を行うための注意点までをまとめて確認します。焦らず一つずつ準備していきましょう。

## 推奨PCスペックの目安

複数の仮想マシンを同時に起動して演習を進めるため、通常のPC作業よりも高い性能が求められます。以下を目安にしてください。

| 項目 | 目安 | 根拠 |
| --- | --- | --- |
| メモリ(RAM) | 16GB以上 | 仮想マシンを複数同時に起動するため、各VMに2〜4GBずつ割り当てても余裕を持たせる必要があるため |
| CPU | 4コア以上、仮想化支援機能(Intel VT-x/AMD-Vなど、仮想マシンを効率よく動かすためのCPU機能)に対応 | 仮想化支援機能は仮想マシン起動の必須要件であり、コア数が少ないと動作が重くなるため |
| 空きディスク容量 | 100GB以上 | OSイメージ(ISOファイル。OSをインストールするための配布ファイル)と仮想ディスクを複数用意すると、1台あたり数十GBを消費するため |
| ストレージ種別 | SSD推奨 | HDDでは仮想マシンの起動やディスクへの読み書きが遅く、演習の待ち時間が増えるため |
| インターネット回線 | 安定した接続 | OSイメージのダウンロードやAWSへの接続に必要なため |

> **覚え方のコツ**: 数字をそのまま暗記しなくても、「仮想マシン1台あたりメモリ2〜4GB・ディスク20〜40GB」を基準に、演習で同時に使う仮想マシンの台数をかけ算すれば必要なスペックを見積もれます。たとえば仮想マシンを3台同時に起動する演習なら、メモリは2〜4GB×3台+ホストOSの分でおよそ16GB、ディスクも1台あたり20〜40GB×台数分+OSイメージの保存分でおよそ100GBという具合です。表の数字はこの考え方から逆算した目安だと覚えておくと忘れにくくなります。

自分のPCの現在のメモリ量やディスク空き容量は、次のコマンドで確認できます。

```powershell
# Windowsで搭載メモリ量をGB単位で確認する
(Get-CimInstance Win32_ComputerSystem).TotalPhysicalMemory / 1GB

# Cドライブの空き容量を確認する(Used・FreeともにGB単位で表示されます)
Get-PSDrive C
```

```bash
# macOSで搭載メモリ量を確認する(バイト単位で表示されるので、目安として10億で割るとおおよそのGB数になります)
sysctl hw.memsize

# macOS/Linuxで空きディスク容量を確認する
df -h
```

## VirtualBoxの導入

演習では、無料の仮想化ソフトである「VirtualBox」を使用します。VirtualBoxを使うと、1台のホストPCの中に複数の仮想マシンを作成し、それぞれに別のOSをインストールして動かせます。

VirtualBoxは、必ず開発元の公式サイトから入手してください。お使いのホストPCのOS(Windows/macOS/Linuxなど)に対応したインストーラーを選び、案内に従ってインストールします。あわせて配布されている「Extension Pack」(USB対応などの追加機能を提供する拡張パッケージ)も導入しておくと、後の演習で困りにくくなります。

- [ ] VirtualBox本体を公式サイトからダウンロード・インストールした
- [ ] Extension Packも導入した
- [ ] インストール後にホストPCを再起動した

インストールが正しく完了したかは、コマンドラインからバージョンを確認すると分かります。

```bash
VBoxManage --version
```

もしホストPCのBIOS/UEFI(PC起動時のハードウェア設定画面)で仮想化支援機能が無効になっていると、仮想マシンが起動できないことがあります。その場合は設定画面から機能を有効化してください。

## VirtualBoxのネットワークアダプターの種類

VirtualBoxで仮想マシンを作るとき、ネットワークアダプターの種類を選ぶ場面があります。代表的な3種類の違いを整理します。

| 種類 | 概要 | この演習パックでの位置づけ |
| --- | --- | --- |
| NAT | 仮想マシンから外部(インターネット)へは通信できるが、外部から仮想マシンへは直接アクセスできない。仮想マシン同士も標準では通信不可 | インターネット接続用の補助アダプターとして併用することがある |
| ホストオンリーアダプター | ホストPCと仮想マシンの間、および仮想マシン同士だけで通信できる、外部から隔離されたプライベートなネットワーク | **この演習パックの基本アダプター** |
| ブリッジアダプター | 仮想マシンを自宅LANに直接つながった1台の機器のように見せる。ルーターからIPアドレスが割り当てられ、他の家庭内機器とも通信できる | 特定の回でのみ限定的に使用 |

この演習パックでは、基本的に「ホストオンリーアダプター」を軸に構成します。仮想マシン同士を安全に通信させながら、自宅LANや外部インターネットから直接アクセスされない状態を保てるためです。パッケージのダウンロードなど仮想マシンからインターネットへ出る必要がある回では、ホストオンリーアダプターに加えてNATアダプターも1枚追加する構成を案内します。ブリッジアダプターは、外部に晒すリスクが増すため、特別に指示のある回以外では使用しません。

> **覚え方のコツ**: 「NAT=外出はできても部屋番号を教えていないホテルの一室」「ホストオンリー=寮の中だけで住人同士が行き来できる学生寮」「ブリッジ=表札を出した一戸建て」とイメージすると、外部からどこまで見える・入れるかの違いを覚えやすくなります。この演習パックの基本は、外の世界から閉じている「学生寮(ホストオンリー)」です。

## 演習で使用するOSイメージ

この演習パックでは、主に次のOSイメージを使用します。

- **Ubuntu Server LTS**(Long Term Support、長期サポート版):サーバー用途で広く使われているLinuxディストリビューション(Linuxカーネルにさまざまなソフトウェアを組み合わせ、OSとして配布用にまとめたもの)の一つです。LTS版は数年単位でセキュリティ更新が提供され、無料で利用期限もありません。
- **Windows Server 評価版**:マイクロソフトが提供する評価版(トライアル版)で、機能はほぼ製品版と同じですが、利用できる期間(180日間など)に制限があります。期限を過ぎるとライセンス上使用できなくなるため、演習の進行スケジュールを見て入手タイミングを調整してください。

いずれのOSイメージも、必ずそれぞれの公式配布元(Ubuntuの公式サイト、Microsoftの公式評価版提供サイトなど)から直接入手してください。検索結果に出てくる第三者のミラーサイトや転載サイトは、ファイルが改変されているおそれがあるため避けましょう。

- [ ] Ubuntu Server LTSのISOファイルを公式サイトから入手した
- [ ] Windows Server評価版のISOファイルを公式サイトから入手した(評価期間・登録要否を確認済み)
- [ ] ダウンロードしたファイルのチェックサム(ファイルが壊れたり改変されたりしていないかを確認するための値)を公式サイト記載の値と照合した

チェックサムは次のように確認できます。

```bash
sha256sum ubuntu-server.iso
```

```powershell
Get-FileHash .\WindowsServer_Eval.iso -Algorithm SHA256
```

チェックサムは全ての文字を1文字ずつ目で追う必要はありません。公式サイトに書かれた値と、コマンドの出力結果の先頭数文字・末尾数文字を見比べるだけでも、ファイルの取り違えや破損には十分気づけます。

## AWSアカウントの準備

一部の演習では、クラウドサービスであるAWS(Amazon Web Services)上にもサーバーを構築します。新しくAWSアカウントを作成する際は、次の点に注意してください。

- **クレジットカードの登録が必須です。** 無料利用枠の範囲内で使う場合でも、本人確認や不正利用防止のためカード情報の登録が求められます。
- **無料利用枠(Free Tier)には期間・対象サービス・使用量の条件があります。** これまでは「アカウント作成から一定期間だけ無料になるサービス」「期間を問わず無料の範囲があるサービス」「短期間の試用枠があるサービス」など複数の種類が用意されてきましたが、提供内容は見直されることがあるため、演習を始める前に必ずAWS公式サイトで最新の条件を確認してください。
- **請求アラート(利用金額が設定した金額を超えたら通知してくれるしくみ)を必ず設定しましょう。** アカウント作成後すぐに、AWSマネジメントコンソール(AWSの各種サービスをブラウザから操作するための管理画面)の請求関連の設定画面から、通知先メールアドレスと金額のしきい値を登録しておくと、想定外の課金に早く気づけます。

> **コツ**: しきい値の金額に迷ったら、まずは1〜5ドルなど低めの金額で1つ設定しておくと安心です。しきい値は後からいつでも追加・変更できるので、「とりあえず低めに1つ」から始めるのがおすすめです。

- [ ] クレジットカードを登録した
- [ ] 無料利用枠の対象条件(期間・サービス・使用量上限)を公式サイトで確認した
- [ ] 請求アラート(予算アラート)を設定した
- [ ] ルートユーザー(アカウント作成時に自動的に発行される、すべての操作が可能な最上位の管理者アカウント)での日常作業を避け、権限を絞った別ユーザーを用意する準備をした

## 安全に演習を行うための注意事項

検証環境は自由に作って壊して学べるのが利点ですが、次の点を守らないと思わぬトラブルにつながります。

- [ ] 検証環境を自宅ネットワークの外部に公開しない(ポート転送やブリッジ接続を安易に有効化しない、AWSのセキュリティグループ〈仮想サーバーへの通信を許可・拒否するファイアウォールのようなしくみ〉を全世界に開放しない)
- [ ] 本番環境と検証環境を混同しない(演習用の仮想マシンやAWSリソースには、本番用と紛れない名前・タグを付ける)
- [ ] パスワードは使い回さない(演習専用の、他のサービスと重複しない強固なパスワードを設定する)
- [ ] 演習が終わったら不要な仮想マシンやAWSリソースを削除・停止し、放置による課金や設定ミスを防ぐ

## まとめ

演習環境の準備は地味に見えますが、ここで手を抜くと後の演習でつまずく原因になりやすい部分です。PCスペックの確認、VirtualBoxのインストールとネットワークアダプターの基礎、OSイメージの安全な入手、AWSアカウントの注意点、そして安全対策までを一つずつ済ませておけば、以降の演習にスムーズに取り組めます。チェックリストを一つずつ埋めながら、準備を進めていきましょう。
