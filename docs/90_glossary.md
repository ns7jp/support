# 用語集

サーバー構築エンジニアを目指す学習の中で出てくる基礎用語を、カテゴリ別にまとめました。各用語の末尾にある「→ 案件0X」は、その用語が実際に使われる案件(演習)番号の目安です。使い方や覚え方のコツは、次のセクションで紹介します。

## 用語集の使い方(暗記のコツ)

一度にすべて覚えようとすると疲れてしまいます。以下のコツを参考に、少しずつ自分のものにしていきましょう。

- **辞書として使う**: 演習中にわからない言葉が出てきたら、まずこのページで検索して意味を確認しましょう。
- **声に出す・書き出す**: 用語と一言説明をセットで声に出して読む、あるいはノートに書き写すと記憶に残りやすくなります。
- **案件と紐づけて覚える**: 「→ 案件0X」を手がかりに、実際にその案件を進めるときにもう一度この用語集を見返してみましょう。「読んだだけの知識」を「手を動かした経験」に変えると、格段に忘れにくくなります。
- **たとえ話で理解する**: 抽象的な用語は、身近なものに置き換えると頭に入りやすくなります。

| 用語 | たとえ |
| --- | --- |
| ファイアウォール | 建物の入り口に立つ警備員(許可された人だけを中に通す) |
| DNS | 名前から番号を調べる電話帳(名前からIPアドレスを調べる) |
| ドメイン・OU・GPO | 会社(ドメイン)の中の部署(OU)ごとに定める就業規則(GPO) |
| VPC・EC2・セキュリティグループ | 自分の土地(VPC)に建てた建物(EC2)を守る門番(セキュリティグループ) |

- **語呂合わせを作る**: たとえばOSI参照モデルの7階層(物理→データリンク→ネットワーク→トランスポート→セッション→プレゼンテーション→アプリケーション)は、英語圏では頭文字を取った "Please Do Not Throw Sausage Pizza Away" という語呂合わせが有名です。自分なりの日本語の語呂合わせを考えてみるのもおすすめです。
- **自分でテストする**: 説明文を隠して用語を答えられるか、逆に用語だけを見て説明できるかを繰り返し確認しましょう。

一通り演習が進んだら、以下のチェックリストで理解度を振り返ってみてください。

- [ ] 各カテゴリの用語を、説明を見なくても一言で言える
- [ ] それぞれの用語がどの案件で登場したか、だいたい思い出せる
- [ ] 苦手な用語には印をつけて、演習の合間に何度も見返している

## ネットワーク

- **IPアドレス**: ネットワーク上の機器を識別するための住所のような番号。→ 案件01, 案件02で登場
- **サブネットマスク**: IPアドレスを「ネットワーク部」と「ホスト部」に分けるための値。→ 案件01, 案件02で登場
- **デフォルトゲートウェイ**: 自分のネットワークの外(インターネットなど)へ通信するときの出入り口となる機器。→ 案件01, 案件02で登場
- **MACアドレス**: ネットワーク機器に割り当てられた固有の物理アドレス(Media Access Control Address)。→ 案件01で登場
- **DNS**: ドメイン名(例: example.com)をIPアドレスに変換する仕組み(Domain Name System)。→ 案件01, 案件02で登場
- **DHCP**: IPアドレスなどのネットワーク設定を機器に自動的に割り当てる仕組み(Dynamic Host Configuration Protocol)。→ 案件01, 案件02で登場
- **ポート番号**: 1台の機器の中で、どのアプリ・サービス宛の通信かを区別する番号。→ 案件05, 案件06, 案件08で登場
- **`ping`**: 相手の機器と通信できるかを確認するコマンド。→ 案件02で登場
- **`tracert`(Linuxでは`traceroute`)**: 通信が相手先までどの経路を通っているかを調べるコマンド。→ 案件02で登場
- **ルーティング**: 異なるネットワーク同士の間で通信経路を決めること。→ 案件02で登場
- **NAT**: プライベートIPアドレスとグローバルIPアドレスを相互に変換する技術(Network Address Translation)。→ 案件07で登場
- **ブリッジ接続**: 仮想マシンを物理ネットワークに直接つないだように見せる接続方式。→ 案件07で登場
- **OSI参照モデル**: ネットワーク通信の仕組みを7つの階層に分けて考えるための基礎理論(Open Systems Interconnection)。→ 案件02で登場

## OS・サーバー

- **シェル**: ユーザーが入力したコマンドをOSに伝える対話プログラム(例: bash)。→ 案件05で登場
- **`sudo`**: 一般ユーザーが管理者権限でコマンドを実行するための仕組み(Linux)。→ 案件05で登場
- **パーミッション**: ファイルやディレクトリに対する読み取り・書き込み・実行の権限設定。`chmod`コマンドなどで変更します。→ 案件05, 案件08で登場
- **ホスト名**: ネットワーク上で機器を識別するための名前。→ 案件01, 案件05で登場
- **SSH**: 離れたサーバーに安全に接続して操作するための通信プロトコル(通信の取り決め。Secure Shellの略)。→ 案件05, 案件08で登場
- **鍵認証(公開鍵認証)**: パスワードの代わりに「鍵」のペアを使って、SSH接続時に本人確認をする方式。→ 案件05, 案件08で登場
- **`systemctl`**: Linuxでサービス(常駐プログラム)の起動・停止・状態確認を行うコマンド。→ 案件05, 案件06で登場
- **`cron`**: 決まった時刻・周期でコマンドを自動実行する仕組み(Linux)。設定は`crontab`コマンドで編集します。→ 案件09で登場
- **ログローテーション**: ログファイルが肥大化しないよう、一定周期で分割・削除する仕組み。Linuxでは`logrotate`というツールがよく使われます。→ 案件09で登場
- **ロードアベレージ**: サーバーの処理待ちの度合いを示す負荷の指標。`uptime`コマンドや`top`コマンドなどで確認できます。この演習パックの案件では直接扱いませんが、サーバー運用でよく使う基礎知識として覚えておきましょう。
- **パッケージ管理**: ソフトウェアの導入・更新・削除をまとめて管理する仕組み(例: apt, yumなど)。→ 案件05で登場
- **マウント**: ディスクや外部ストレージをOSから使えるように組み込む操作。→ 案件07で登場

## Windows・AD

- **Active Directory(AD)**: Windows環境でユーザーやPCを一元管理するディレクトリサービス(組織内の情報をまとめて管理する仕組み)。→ 案件04で登場
- **ドメイン**: ADによって一元管理されるユーザー・PCの集合体。→ 案件04で登場
- **ドメインコントローラー**: ADの中心となり、ユーザー認証や設定配布を担うサーバー。→ 案件04で登場
- **OU(組織単位)**: AD内でユーザーやコンピューターをグループ分けして管理するための箱。→ 案件04で登場
- **GPO(グループポリシーオブジェクト)**: OUなどに適用する設定ルールの集まり。→ 案件04で登場
- **NTFS権限**: ファイルやフォルダーそのものに設定するアクセス権限(NTFSはWindowsの標準的なファイルシステム形式)。→ 案件03で登場
- **共有権限**: ネットワーク越しにフォルダーへアクセスする際の権限設定(Windows)。→ 案件03で登場
- **PowerShell**: Windowsを操作・自動化するためのコマンドラインツール兼スクリプト言語。→ 案件01, 案件04で登場
- **レジストリ**: Windowsの設定情報を保存しているデータベース。この演習パックの案件では直接扱いませんが、Windows運用の基礎知識として覚えておきましょう。

**NTFS権限と共有権限は混同しやすいポイントです。** ネットワーク越しに共有フォルダーへアクセスする場合、両方の設定のうち「より厳しい(制限が強い)方」が実際に適用されます。

| 観点 | NTFS権限 | 共有権限 |
| --- | --- | --- |
| 設定できる場所 | ファイル・フォルダー単位 | 共有フォルダー単位 |
| ローカルログオン時 | 適用される | 適用されない |
| ネットワーク経由のアクセス時 | 適用される | 適用される |

## セキュリティ

- **脆弱性**: システムに存在する、攻撃の糸口になり得る弱点。この演習パックの案件では直接扱いませんが、セキュリティを考えるうえでの基礎知識として覚えておきましょう。
- **マルウェア**: ウイルスやランサムウェアなど、悪意のあるソフトウェアの総称。→ 案件01で登場
- **ブルートフォース攻撃**: パスワードなどをしらみつぶしに試して突破しようとする攻撃手法。→ 案件10で登場
- **ファイアウォール**: 許可されていない通信を遮断し、外部からの不正アクセスを防ぐ仕組み。→ 案件05, 案件06, 案件10で登場
- **`ufw`**: Linuxに標準搭載されているiptablesというファイアウォール機能を、簡単な命令で操作できるようにしたコマンド(Uncomplicated Firewallの略)。→ 案件05, 案件06, 案件10で登場
- **fail2ban**: ログを監視し、不正なログイン試行を繰り返すIPアドレスを自動的に遮断するツール。→ 案件10で登場
- **多要素認証(MFA)**: パスワードに加えてスマホ認証などを組み合わせ、本人確認を強化する仕組み。→ 案件10で登場
- **セキュリティパッチ**: 脆弱性を修正するために配布される更新プログラム。→ 案件01(Windows Update), 案件05(apt upgrade)で登場
- **インシデント対応**: 障害やセキュリティ事故が発生した際に、原因調査・復旧・再発防止を行う一連の対応。→ 案件10で登場

## クラウド

- **AWS(Amazon Web Services)**: Amazonが提供するクラウドサービスの総称。→ 案件08で登場
- **VPC**: AWS上に構築する、自分専用の仮想ネットワーク空間(Virtual Private Cloudの略)。→ 案件08で登場(演習ではAWSが用意する既定のVPCを利用します)
- **EC2**: AWS上で仮想サーバーを構築・利用できるサービス(Elastic Compute Cloudの略)。→ 案件08で登場
- **セキュリティグループ**: EC2インスタンス(起動して動いている仮想サーバーの実体)などに適用する、通信を制御する仮想ファイアウォール。→ 案件08で登場
- **Elastic IP**: AWSで利用できる、固定のグローバルIPアドレス。→ 案件08で登場
- **S3**: AWSが提供するファイル(オブジェクト)保存用のストレージサービス(Simple Storage Serviceの略)。この演習パックの案件では直接扱いませんが、AWSの基礎知識として覚えておきましょう。
- **IAM**: AWS上の各サービスやデータに対して、誰が何をできるかを管理する仕組み(Identity and Access Managementの略)。→ 案件08の発展課題で登場(実務ではルートユーザーではなくIAMユーザーで運用するのが基本です)

## 運用

- **仮想化**: 1台の物理マシン上に、複数の仮想的なコンピューター(仮想マシン)を作り出す技術。→ 案件07で登場
- **VirtualBox**: 手元のPCで仮想マシンを作成・実行できる無償の仮想化ソフト。→ 案件07で登場
- **スナップショット**: 仮想マシンやディスクのある時点の状態を保存し、後で復元できるようにする機能。長期保存用のバックアップとは目的が異なる点に注意しましょう。→ 案件07, 案件04で登場
- **バックアップ**: データやシステムの複製を別の場所に保存しておくこと。→ 案件09で登場
- **リストア**: バックアップしたデータをもとの状態に復元すること。→ 案件09で登場
- **冗長化**: 機器やシステムを複数用意し、一部が故障してもサービスを継続できるようにすること。この演習パックの案件では直接扱いませんが、可用性を考えるうえでの基礎知識として覚えておきましょう。
- **SLA(サービスレベルアグリーメント)**: サービス提供者が利用者に約束する稼働率などの品質基準。この演習パックの案件では直接扱いませんが、運用を考えるうえでの基礎知識として覚えておきましょう。

一度にすべて覚える必要はありません。案件を進めながら、この用語集を「辞書」として何度も開いてみてください。繰り返し使ううちに、自然と用語が体に染み込んでいきますよ。
