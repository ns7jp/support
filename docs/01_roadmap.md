# 学習ロードマップ

このドキュメントは、サーバー構築エンジニアを目指すための全10案件(実際に手を動かして学ぶ実践プロジェクトのこと)を、無理なく8週間で完走するための「地図」です。最初に全体像をつかんでおくと、途中で迷ったときにも「今どこにいるか」がわかり、挫折しにくくなります。

まずは8週間の全体プランを確認し、そのあとで1週あたりの学習ペースの目安、レベル別の進め方、案件同士のつながり、つまずいたときの対処法という順に見ていきましょう。

## 8週間モデルプラン

全10案件を8週間で完走するための標準プランです。「取り組む案件」に加えて、「振り返りのタイミング」も決めておくと、詰め込みすぎを防げます。

| 週 | 取り組む案件 | この週のゴール | 振り返りのタイミング(目安) |
| --- | --- | --- | --- |
| 1週目 | 環境準備(`docs/02`) + 案件01(PC初期セットアップ) | 学習用PCと演習環境を整え、Windowsのキッティング作業の基本の流れをつかむ | 日曜に、環境構築の手順とよく使った基本コマンドを見直す |
| 2週目 | 案件02〜03(ネットワーク疎通切り分け・共有フォルダ権限) | ネットワークの基礎と、Windows環境での運用トラブル対応の考え方を身につける | 土曜に案件02、日曜に案件03の内容をそれぞれ振り返る |
| 3週目 | 案件07(仮想化環境構築) + 案件04(Active Directory) | VirtualBoxで検証環境を構築し、その上でActive Directoryのユーザー・グループ管理を体験する(案件04は案件07の仮想化環境が前提です) | 週末のどこかで、仮想化ソフトの操作と合わせてOU・グループの考え方を振り返る |
| 4週目 | 案件05(Linuxサーバー初期構築) | Linuxサーバーの初期設定とSSH接続の安全な設定を身につける(案件06・09・10の土台になる重要な案件) | 日曜に、以降の土台になる案件なので理解度を必ずセルフチェックする |
| 5週目 | 案件06(Webサーバー構築) | 案件05のサーバー上にNginxを導入し、社内向けWebページを公開する | 土曜に、案件05との接続部分(SSH・ファイアウォール設定)を中心に復習する |
| 6週目 | 案件08(クラウド基礎構築・AWS) | AWSの無料利用枠でEC2インスタンスを構築し、リモートから安全に接続する | 日曜に、コスト管理(インスタンスの停止・削除)の手順を必ず再確認する |
| 7週目 | 案件09〜10(バックアップ・ログ監視、セキュリティインシデント対応) | 運用・セキュリティ系の案件に取り組む(いずれも案件05のサーバーを対象にします) | 週末に、案件09と案件10の共通点(ログの確認・自動化)を整理する |
| 8週目 | 全体振り返り + ポートフォリオ仕上げ | これまでの手順書を見直し、成果物(ポートフォリオ=学習成果をまとめて第三者に見せる資料)を整理する | この週全体を振り返り期間として使う |

## 学習ペースの目安

フルタイムで学習時間を確保できる人は少ないはずです。このロードマップでは、以下のような現実的なペースを想定しています。

| 曜日 | 目安時間 | 内容 |
| --- | --- | --- |
| 平日(月〜金) | 1時間 × 5日 | 手順書を読む、コマンドを実際に打つ、詰まった点をメモする |
| 週末(土・日) | まとめて2〜4時間 | 平日にできなかった作業の続き、振り返り、次の案件の予習 |

週あたり合計7〜9時間が目安です。忙しい週があっても大丈夫です。ロードマップは「目安」であって「締め切り」ではないので、遅れても順番さえ守れば必ず追いつけます。

## レベル別おすすめルート

自分の経験に合わせてスピード配分を変えましょう。無理に標準ペースに合わせる必要はありません。

| タイプ | 目安対象者 | 進め方のコツ |
| --- | --- | --- |
| じっくり基礎固めコース | PC操作やコマンド入力にまだ不安がある人 | 案件01〜03に2〜3週間かけてOK。焦らず1つずつ確実に身につけましょう |
| 標準コース | 本ロードマップどおりで問題ない人 | 上記の8週間プランをそのまま実行しましょう |
| 加速コース | PC操作に慣れている人・IT系資格保有者 | 案件01は流し読み程度にして、案件02以降に時間を厚く配分。浮いた時間は案件06・09など応用案件の復習に充てましょう |

## 案件同士の前提関係

案件には、取り組む順序に気をつけたいものがあります。先に依存関係を頭に入れておくと、「なぜこの順番なのか」がわかり、迷わず進められます。

- 案件01 → 案件02 → 案件03 が基本ライン(PCキッティング → ネットワーク基礎 → Windows運用の基本操作)です。順番どおりに進めましょう。
- 案件04(Active Directory)に取り組むには、事前に案件07(仮想化環境構築)でVirtualBoxなどの検証環境を用意し、その上にWindows Serverの評価版環境を構築しておく必要があります。8週間プランでは案件07を先に済ませてから案件04に進む順番にしています。
- 案件05(Linuxサーバー初期構築)は、以降の複数の案件で土台として使われる重要な案件です。案件05から次のように枝分かれします。
  - 案件05 → 案件06(Webサーバー構築。案件05のサーバーの上にNginxを導入します)
  - 案件05 → 案件09(バックアップ・ログ監視。案件05のサーバーを対象にバックアップを設定します)
  - 案件05 → 案件10(セキュリティインシデント対応。案件05のサーバーを対象に不審ログインを調査します)
- 案件08(クラウド基礎構築・AWS)は、AWS上に新しく環境を作るため単独でも進められますが、案件05でSSH接続や鍵認証の考え方に慣れておくと、より理解がスムーズになります。
- 案件09と案件10はどちらも案件05のサーバーを対象にするため、順番はどちらが先でも構いませんが、案件09(バックアップ)を先に行っておくと、案件10のインシデント対応時に「バックアップから復旧できる状態か」を意識しながら学べます。

図にすると、次のようなイメージです。

```
案件01 → 案件02 → 案件03

案件07(仮想化環境構築) → 案件04(Active Directory)

案件05(Linuxサーバー初期構築) ─┬─→ 案件06(Webサーバー構築)
                                ├─→ 案件09(バックアップ・ログ監視)
                                └─→ 案件10(セキュリティインシデント対応)

案件08(クラウド基礎構築・AWS)は単独でも進行可能(案件05の知識があるとより理解しやすい)
```

## 学習が停滞したときのヒント

手が止まってしまうのは誰にでもあることです。次のチェックリストを試してみてください。

- [ ] 完璧を求めず、まず手を動かす(エラーが出ても、一旦最後まで手順を進めてみる)
- [ ] 手順書を自分の言葉で書き直してみる(コピペではなく、理解できているかどうかの確認になります)
- [ ] コマンドは丸暗記しようとせず、オプションの意味を1文字ずつ分解して覚える(例: `ls -la` の `-l` はlong=詳細表示、`-a` はall=隠しファイルも含めて表示、という意味です。意味とセットで覚えると忘れにくくなります)
- [ ] 1週間後に、手順書を見ずに同じコマンドを打てるか試してみる(思い出しながら使う練習は、読み返すだけの復習より記憶に残りやすいと言われています)
- [ ] わからない用語が出たら、その場で用語集(`docs/90_glossary.md`)を確認する習慣をつける
- [ ] 同じ箇所で2回以上詰まったら、その日は一度切り上げて翌日リセットして取り組む
- [ ] エラーメッセージは全文を読み、キーワードで検索する(一部だけで判断しない)

学習ログとして、案件ごとに気づきをメモしておくと振り返りが楽になります。フォルダだけ先に用意しておきましょう。

```bash
mkdir -p ~/study/portfolio/case01
touch ~/study/portfolio/case01/notes.md
```

8週間という期間は、あくまで進み方の目安です。大切なのはスピードではなく、最後までやり切ること。焦らず一歩ずつ、この地図を片手に案件を積み上げていきましょう。
